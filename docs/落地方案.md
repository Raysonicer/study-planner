## 1. 产品定义

### 1.1 定位
面向个人学习者的「目标 → 任务分解 → 日程 → 统计 → 周复盘」闭环工具。数据完全本地（单文件），可备份、可迁移、可自托管。

### 1.2 核心场景
- **晨间规划（3 分钟）**：看今日目标 → 把任务拖进日程时间块 → 开始执行
- **执行中**：任务/子任务打勾，进度条实时更新，逾期自动标红
- **周日晚复盘（15 分钟）**：打开周复盘 → 系统自动生成本周数据快照 → 写 KPT（Keep/Problem/Try）+ 下周计划

### 1.3 非目标（明确不做，防止范围蔓延）
- 不做团队协作/多用户（P2 之前）
- 不做"项目/空间"层级（目标即顶层组织单元）
- 不做复杂习惯周期规则（那是 uhabits 的领域，学习场景不需要）
- 不做 AI 自动生成计划（P2+ 可选探索）

## 2. 功能规格（P0 / P1 / P2）

### 2.1 P0 —— 第一版必须（对应五大模块）

**模块 1：学习目标**
- 日目标：CRUD、绑定日期、打勾完成/撤销、未完成的在当天结束后显示"未达成"
- 周目标：CRUD、绑定 ISO 周；两种模式：
  - 一次性型：打勾即完成
  - 每日打卡型：设每周应打卡天数（默认 5），达成率 = 实际打卡天数 / 应打卡天数
- 目标可关联任意多个任务（达成率的参考口径）
- 支持排序、Markdown 备注、归档

**模块 2：任务分解**
- 任务树：任意层级子任务；UI 默认展示两级，可展开收起
- 字段：标题、Markdown 备注、优先级(0-3)、截止日、预估时长、标签、关联目标（可空=自由任务）
- 批量分解：粘贴多行文本，一键生成 N 个子任务（高频操作，必须有）
- 完成交互：打勾/撤销；父任务进度条 = 已完成子任务数 / 总子任务数；子任务全部完成时**提示**可一键完成父任务（不强制自动，做成设置项）
- 筛选：按状态 / 目标 / 标签 / 截止日；支持手动排序

**模块 3：日程管理**
- 日视图：24 小时时间轴（半小时刻度），时间块 CRUD
- 时间块字段：起止时间、标题、颜色、可关联任务、备注
- 交互：点击空白处创建（默认 1 小时）、编辑弹窗、拖动平移（P0）；拖拽改时长放 P1
- 任务联动：任务侧栏可拖入时间轴生成块；关联任务完成后，对应时间块高亮显示

**模块 4：任务管理（统计可视化）**
- 今日面板：日目标达成率、今日任务完成率、日程占用时长、逾期任务数
- 热力图：日 × 周 综合完成度（GitHub 贡献图风格），点击某天下钻日详情
- 周统计页：近 8 周完成率折线、本周任务分布（按目标/标签）、未完成任务清单、日目标达标率趋势
- **统计口径见 §5，开工前冻结**

**模块 5：复盘**
- 周复盘列表（按周倒序），每周一条
- Markdown 编辑器（源码/预览切换）
- 内置模板：本周统计快照（自动生成）+ KPT 三栏 + 下周计划
- **快照冻结**：保存时生成 JSON 快照（完成率、未完成清单、时间分布、目标达成），此后修改任务数据不影响历史复盘

### 2.2 P1 —— 增强
- 番茄钟/专注计时（关联任务，时长计入统计）
- 目标模板 / 周模板（一键生成本周结构）
- 数据导出：JSON（全量备份）、Markdown（周报）、CSV（统计明细）
- 浏览器通知（截止提醒）
- PWA 安装 + 移动端响应式适配

### 2.3 P2 —— 进阶
- 跨设备同步（WebDAV 或 git）
- 账号与多用户
- 可选：AI 复盘助手（LLM 生成复盘草稿，人工确认）

## 3. 总体架构与技术选型

### 3.1 决策表

| 层 | 选型 | 理由（回扣调研） |
|---|---|---|
| 前端框架 | Vue 3 + TypeScript + Vite + Pinia + Vue Router | 中文生态最好；Vikunja 同款路线被验证 |
| UI 组件 | Element Plus（备选 Naive UI） | 组件齐全、中文文档 |
| 图表 | Apache ECharts | 热力图/折线/环形图一站解决 |
| Markdown 编辑器 | md-editor-v3 | 复盘模块即用，Vue3 原生 |
| 后端 | Go 1.24 + Echo v4 | 单二进制 + embed 前端，Vikunja 验证过的最佳部署形态 |
| ORM / DB | GORM + SQLite（modernc.org/sqlite 纯 Go 驱动） | **免 CGO**，Windows 开发与交叉编译无痛；数据单文件 |
| 迁移 | golang-migrate | schema 版本化 |
| API 文档 | swag 生成 OpenAPI | 前后端契约 |
| 部署 | Docker 多阶段构建 + compose | 一行命令起服务，data 目录外挂 |
| 测试 | Go testify + 前端 Vitest（E2E 选 Playwright） | |
| CI | GitHub Actions（lint + test + build + release） | |

**备选方案（如想全程 TypeScript）**：Vue3 + Node(Fastify 或 NestJS) + Prisma + better-sqlite3。优点：单语言、迭代快；代价：部署需 Node 运行时、长期性能与资源占用不如 Go。**本方案主推 Go 路线（已确认）**——单二进制部署最简单、内存占用低；调研显示该形态是自托管工具的最优解。

### 3.2 架构（文字版）

```
浏览器 Vue3 SPA ──HTTP /api/v1──> Go(Echo) ──> Service 层（统计聚合/复盘快照/目标达成度）
                                      │
                              Store(GORM) ──> SQLite 单文件（data/app.db）
```

部署形态：`app` 单二进制（内嵌 web/dist）或 Docker 镜像；程序与数据分离；启动时自动备份 SQLite 到 data/backups/（保留最近 14 份）。

### 3.3 关键工程决策
1. **日期处理**：一律使用本地日期字符串 `YYYY-MM-DD` 存储与传输，时间用分钟数（0-1439）。不做 UTC 换算——单机个人应用里时区转换是 bug 高发区，直接规避
2. **统计以事件流为唯一事实源**（见 §4 D1）
3. **单用户免登录**：P0 不做认证；代码中预留 users 表与鉴权中间件位置
4. **SQLite 开 WAL**；备份策略内建
5. 前端 API 类型：由 OpenAPI 手工维护一份 types.ts（量小，够用）

## 4. 数据模型设计

### 4.1 实体关系概览

```
goals 1─n goal_checkins（打卡事件流）
goals 1─n tasks（task.goal_id，可空）
tasks 1─n tasks（parent_id 自引用树）
tasks 1─n task_events（完成事件流）
tasks 1─n blocks（日程块，task_id 可空）
reviews：按 week_start 唯一，内嵌 stats_snapshot JSON
```

### 4.2 表结构

**goals**
| 字段 | 类型 | 说明 |
|---|---|---|
| id | INTEGER PK | |
| title | TEXT | |
| goal_type | TEXT | day / week |
| date | TEXT | day 型绑定日期 YYYY-MM-DD（可空） |
| week_start | TEXT | week 型绑定周一 YYYY-MM-DD（可空） |
| checkin_days | INTEGER | week 打卡型：每周应打卡天数 1-7，默认 5 |
| status | TEXT | active / done / archived |
| note | TEXT | Markdown |
| sort | INTEGER | |
| completed_at | TEXT | |
| created_at / updated_at | TEXT | |

**goal_checkins**（打卡事件流）
| id / goal_id / checkin_date / created_at | 唯一索引 (goal_id, checkin_date) |

**tasks**
| 字段 | 说明 |
|---|---|
| id / title / note(MD) | |
| parent_id | 可空，自引用 |
| goal_id | 可空，关联日/周目标 |
| status | todo / doing / done |
| priority | 0-3 |
| due_date | YYYY-MM-DD 可空 |
| est_minutes | 预估时长 |
| tags | TEXT 存 JSON 数组（P0 不做独立标签表，个人规模够用） |
| sort / completed_at / created_at / updated_at | |

**task_events**（任务事件流）
| id / task_id / event_type(created|done|reopen) / occurred_date / occurred_at |

**blocks**（日程时间块）
| id / block_date / start_min / end_min / title / task_id(可空) / color / note / created_at / updated_at | 约束 end_min > start_min |

**reviews**（周复盘）
| id / week_start(UNIQUE) / title / content_md / stats_snapshot(JSON TEXT) / created_at / updated_at |

**focus_sessions**（P1 番茄钟）
| id / task_id / started_at / ended_at / duration_sec / note |

**settings**（key/value）：week_start_day、theme、auto_complete_parent 等

### 4.3 五个关键设计决策（评审重点）

- **D1 事件流原则**：task_events 与 goal_checkins 是所有统计的唯一输入，tasks.status 只是当前态缓存。借鉴 uhabits（checkmarks 事件流聚合出全部指标）——支持"任意历史日期的完成率"回算，且撤销操作不污染历史统计
- **D2 周键统一**：所有周级实体（周目标/周复盘/周统计）用 `week_start = 周一日期` 关联，杜绝跨周归属歧义（周起始日做成设置项，默认周一）
- **D3 目标达成率双口径**：主口径 = 打卡（goal_checkins）；参考口径 = 关联任务完成率（task.goal_id 聚合）。UI 以打卡为主，任务口径作为参考线展示
- **D4 复盘快照冻结**：review.stats_snapshot 保存的是生成时刻的数据 JSON，复盘正文引用快照；此后数据变动不影响已写复盘。**这是相对全部竞品的差异化设计**
- **D5 父任务不强制自动完成**：子任务全完成时仅提示，避免误判与撤销成本；自动完成做成设置项

## 5. 统计口径定义（开工前冻结）

| 指标 | 定义 |
|---|---|
| 日任务完成率 | due_date = 当日 的任务中 status=done 的占比 |
| 日目标达成率 | 当日打卡数 / 当日 active 日目标数 |
| 周任务完成率 | 本周内 due 的任务中 done 占比 |
| 周目标达成率 | 一次性型按 done 计；打卡型按 打卡天数 / checkin_days |
| 综合完成度（热力图） | 0.5 × 日任务完成率 + 0.5 × 日目标达成率（权重可配置）；当天无任务无目标记空 |
| 日程占用 | 当日 blocks 总分钟；完成度 = 已完成关联任务块时长 / 总块时长 |
| 逾期任务 | due_date < 今日 且 status != done |

## 6. API 设计草案（/api/v1，REST JSON）

| 端点 | 说明 |
|---|---|
| GET/POST/PUT/DELETE /goals | 目标 CRUD |
| POST /goals/{id}/checkin · DELETE /goals/{id}/checkin | 打卡 / 撤销 |
| GET/POST/PUT/DELETE /tasks | 任务 CRUD（含 parent_id/goal_id） |
| POST /tasks/{id}/complete · /reopen | 完成 / 重开（写事件） |
| POST /tasks/batch | 批量创建子任务（换行拆分） |
| PATCH /tasks/reorder | 拖动排序 |
| GET/POST/PUT/DELETE /blocks · GET /blocks?from=&to= | 日程块 |
| GET /dashboard?date= | 今日聚合（目标+任务+日程+完成率） |
| GET /stats/daily?date= · GET /stats/weekly?week_start= · GET /stats/heatmap?start=&end= | 统计 |
| GET /reviews/{week_start} · PUT /reviews/{week_start} | 复盘读写 |
| POST /reviews/{week_start}/snapshot | 生成统计快照 |
| GET /export/json · /export/markdown | 导出（P1） |
